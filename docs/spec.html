NewBee OS 产品规格

把你说的那段话整理成可以直接开工的规格：一个核心思想（合同即数据），七个优先模块（交易管理为轴心），四个端（经纪人 App / 经纪人网站 / 客户 App / 客户网站），对标了 2026 年市面上做得最好的 CRM 与交易管理产品。配套的 workflow 与 wireframe 画布已经按这份规格重画。

00结论

一句话：你要做的不是"又一个 CRM"，是一个以合同为数据源的交易操作系统——合同上传一次，其余全部派生。

  1. 核心思想 = 合同即数据（Contract-as-Data）。每份合同 / addendum / amendment 上传后，AI 抽成结构化 key-value（价格、贷款额、Option 费、Earnest Money、各类 contingency 天数、closing date …）写进 Deal。日期引擎、checklist、日程、佣金、买卖费用清单、客户端进度、推送提醒全部从这组 key-value 派生，没有第二次录入。市面上只有 DocJacket / Nekst / ListedKit 这一代新工具在做这件事，而且它们都只做 TC 那一段，没有 CRM、没有客户 App、没有中文。
  2. 第一步做交易管理，但要带上三样最小依赖：联系人（各方角色）、房子（地址主记录）、合同管理（上传 + 抽取 + 确认）。没有这三样，Deal 就是空壳。
  3. 四端共用一个后端、一套领域模型。经纪人 App 和网站是同一套数据的两种密度；客户 App 和网站是同一套 Deal 数据的"只读 + 少量动作"投影（签字、上传、确认、留言）。客户端不是另一个产品，是权限视图。
  4. 交易进度图形化 + 走向判断是你的差异化。里程碑时间线（今天在哪、下一个节点、逾期风险）加上"这笔交易会继续还是会黄"的规则判断（Option 期内 / 贷款审批 / 估价缺口 / 检查谈判 / 各 contingency 的终止条件与 Earnest Money 归属），市面上没有一家把这个做成产品功能。
  5. 后续模块（小区、市场报告、CMA、Listing 报告、营销、Lead capture、小工具）都挂在 Property 和 Deal 两个对象上。先把这两个对象做扎实，后面每个模块都是"读数据 + 套模板"。

02合同即数据：Deal Key-Value Schema

03模块规格（按你定的优先级）

每个模块分"必须有 / 应该有 / AI 增强"三层。必须有 = 第一版就要能用；应该有 = 第一版后两个迭代内；AI 增强 = 有数据后加。

M1 · 交易管理 Transactions轴心模块第一步牵扯所有子模块：联系人、房子、日程、合同、To-do、Checklist、佣金、客户端
必须有
  • Pipeline 看板：列 = 阶段（Lead → Pre-Listing / Pre-Approval → Active / Searching → Offer → Under Contract → Closing → Closed ｜ Terminated），卡片显示下一个关键日期倒计时、风险色、金额；支持 Seller / Buyer / Lease Listing / Tenant / Property Management 五种类型
  • 图形化进度：里程碑时间线（横向）：Effective → Option 期 → 贷款审批 → 估价 → Title/Survey → 最终看房 → Closing → Funding；标出今天、每个节点日期、完成 / 逾期 / 风险
  • Key-Value 面板：第 2 节全部字段，带来源和确认状态；价格变化 / 日期变化历史
  • 日期引擎：从 key-value 算所有 deadline（含 Texas 规则：天数按日历天、截止日落在周末假日顺延的规则可配置）；任一锚点变化 → 重算 → 通知受影响任务与客户端
  • Checklist：按 Playbook（你的 5 套模板）实例化；任务锚定日期；阶段折叠；必备文件清单
  • 各方 Parties：买卖双方、对方 agent、lender、title、inspector、contractor；一键电话 / 短信 / 邮件；每方的沟通历史
  • 文档：上传 / 拍照 / 邮件转发进入；类型标注；版本；抽取状态
  • 佣金：从合同价 + 协议比例 + broker 费率表自动算 GCI / 费用 / NCI；状态随阶段变（Pending → Closed）
  • 交易时间线：沟通、变更、文档、任务完成的统一日志
  • 客户端同步开关：哪些字段 / 文件 / 日期对客户可见
应该有
  • 走向判断（Deal Health）：规则引擎：Option 期是否已过、贷款审批状态、估价结果 vs 合同价（gap）、检查谈判是否达成、Title 是否 clear、HOA 文件是否送达；输出 继续 / 风险 / 可能终止 三档 + 触发条件 + 若终止 Earnest Money / Option Fee 归属
  • 买卖费用清单（Net Sheet）：点开一套房或一笔交易，自动生成卖方净收益 / 买方总花费：佣金、title policy（Texas 费率表）、escrow fee、survey、HOA transfer / resale cert、税费 proration、贷款费用、home warranty、预付款；可导出给客户
  • Amendment 助手：从谈判结果生成 amendment 草稿（价格 / 日期 / repair credit）
  • 价格变化图：Listing 价格 → 降价 → offer → counter → 合同价 → 成交价
  • Hot List / 置顶、模板版本化、并行多笔（同一客户先租后买）
AI 增强 AI
  • 合同 / 检查报告 / 估价报告摘要与问题项抽取
  • "这笔交易现在什么情况、下一步干嘛"一句话问答
  • 对方 agent 画像（历史合作、回复速度、谈判风格备注）
  • 风险预警推送（72h / 24h / 当天）
  • 从历史交易学习你的实际节奏（例如 inspection 通常在 effective 后第 3 天）
M2 · 联系人管理 ContactsM1 前置客户、Vendor、Title 公司、对方 agent 都是联系人，靠"角色"区分
必须有
  • 联系人主记录：多电话 / 邮箱 / 微信名、地址、配偶家人、生日纪念日、语言偏好（中 / 英）
  • 角色标签：客户（买 / 卖 / 租客 / 房东 / 投资）· Vendor（title · lender · inspector · contractor · staging · photographer）· Agent（对方经纪）· 推荐人

  • 关联视图：这个人的所有交易、房子、文档、待办

应该有
  • Vendor 评价与费用记录（哪家 inspector 多少钱、哪家 title 效率高）
  • 推荐关系图（谁介绍了谁，成交多少）
  • 客户端账号邀请（生成登录链接 → 客户 App / 网站）
  • 生日 / 购房周年自动祝福（中英模板）
AI 增强 AI
  • 关系摘要（对标 FUB Smart Summaries）；自动分层建议；下一步跟进建议与消息草稿
  • 名片 / 微信资料截图建档；通话录音转写摘要

客户 App 到底给谁看什么

  • 买家：我的交易进度（里程碑）、下一步要做的事（打款、签字、选保险）、关键日期倒计时、要花多少钱（总费用清单）、文档、看房清单与打分、房贷计算

  • 租客 / 房东：租约状态、付款与到期、维修请求 / 处理进度、续约

客户端权限原则

  • 客户只看到"你勾选公开"的字段和文件，默认公开：进度、日期、下一步、费用清单；默认不公开：佣金、对方信息、内部备注、走向判断
  • 客户动作有限：上传、签字（跳转 e-sign）、确认、留言、打分、预约时间段
  • 登录：手机号 / 邮箱魔法链接，无密码；一个客户可有多笔交易
  • 网站与 App 同一账号同一数据；App 多推送，网站多文档

07实现路线与架构

架构（贴合你的条件：Windows + iPhone + Claude Code）

  • 后端：Supabase（Postgres + Auth + Storage + Edge Functions + Realtime）。一个 schema 服务四端，Row Level Security 区分经纪人 / 客户。
  • 经纪人 App + 客户 App：一个 Expo（React Native）代码库，按角色加载不同导航；EAS Build 云端出 iOS 包，无需 Mac；同一套代码出 Android。
  • 经纪人网站 + 客户网站：Next.js（或 Expo Web），共用组件与 API；客户网站以魔法链接登录。
  • AI：Claude API 做抽取（多模态直接读 PDF / 照片）、摘要、草稿；输出强制 JSON schema（第 2 节）；每字段带来源与置信度。
  • 引擎：日期引擎 / Playbook / Deal Health / Net Sheet 都是纯函数库（TypeScript），前后端共用，可单元测试。
  • 集成：Google Calendar & Gmail API；Twilio（短信）；DocuSign / dotloop（e-sign）；pdf-lib（表单填充）；Expo Notifications（推送）。

先做什么（自用）

  • Deal 表 + Key-Value 版本表 + 日期引擎 + 你的 Seller 模板 → 一笔真实交易跑通
  • 合同拍照 / 上传 → 抽取 → 确认 → 派生（先只做 TREC 1-4 + Financing + HOA addendum）
  • Contacts 最小版 + 导入 CSV；Property 最小版
  • Today 页 + 推送；Google Calendar 分层同步
  • 然后才是客户 App（只读进度 + 推送 + 上传）

08待你拍板的 8 件事

  1. 产品名："NewBee OS" 只是占位。客户端名字要让客户一眼知道是你（NewBee 什么）。
  2. 电子签：集成 DocuSign / dotloop（快、合规）还是先不做（客户端只看不签）？建议 Phase 2 集成。
  3. MLS 数据：Property 字段靠 NTREIS 导出 / 你现有查询流程手动补，还是申请 RESO API（费用与审批）？Phase 1 建议手动 + 抽取。
  4. 微信：没有官方 API。方案：iOS 分享到 App（截图 / 文本）+ OCR 归档。接受吗？
  5. 客户端首发形态：先做客户网站（PWA，可加到主屏、可推送）再上 App Store，还是直接 App？建议先 PWA，省 App Store 审核。
  6. Deal Health 规则来源：先按 Texas 常规规则写死，再由你逐条校订（我可以先起草规则表）。
  7. 费用清单口径：Title policy 费率表、escrow fee、你 broker 的费用表需要你提供一份现行版本。
  8. 数据迁移范围：Wise Agent 只迁联系人 + 5 套模板，进行中交易手动重建（约 10 笔），还是也想把历史交易迁进来做报表？
