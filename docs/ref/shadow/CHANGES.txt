NewBee OS 影子副本 v1.7

最近的改动：
- v1.7：Listing 端的看房做完整（答疑 10-19 · Jason 定）：① 「看房」一个入口两个 tab——我带客户看｜别人看我的挂牌（卖方 + 出租一张表：今天 / 这周 · 等批 · 待反馈 · 没放行，每行点开到那笔交易的卡）；经纪人 App 看房 tab 同样两段，手机上能看谁约了、能放行反馈；② 出租挂牌也挂「看房反馈 · 这套挂牌」卡，「给卖家看」在出租里叫「给房东看」；③ 约看申请按这套挂牌「谁批」分三种（自动确认 / 我批 / 卖家或租客批，挂牌时选一次）：自动确认只记不推；我批——今天页「需要你」+ 第 1 级推送，按钮打开邮件里 BrokerBay 那一场、Jason 自己点批准；卖家或租客批——先标「等卖家批」不打扰，1 小时没人批或离看房不到 3 小时才升级给 Jason（可替批），客户 App 给卖家一行中文提示；批了 / 拒了 / 过期都从邮件认（状态多 requested · declined · expired）；④ 「＋ 记一场」手记微信 / 电话约的；⑤ 对方经纪存电话和邮箱（只经纪人看得到），看完 24 小时没反馈今天页提醒「去要反馈」，AI 起草一句短信、Jason 自己发；⑥ 卖家 / 房东在客户 App 和客户视图看得到约好的日期和时段，不带对方经纪；⑦ 定价信号加「看房不少、没有 Offer」（满 14 天 · 看完 ≥ 6 场 · 0 个在谈 Offer），反馈理由汇总成一条 T2 提议，系统不对卖家说话；示例加了 7575 Showcase Ln（看房 7 场没有 Offer）。红线不变：只读邮件、不登录 BrokerBay / ShowingTime、不代批不代回不代取消、不自动发短信微信邮件、给卖家看的反馈走 5 分钟延迟队列。
- v1.6：把「业主想卖、我在争取 Listing」这条路做成能点通的（答疑 10-06 · Jason 定）：① 房源页「＋ 房源」（一行地址 + 可选 MLS#；同一个地址再加提示已有并跳过去）、「从 Matrix PDF 建档」和房源详情「上传 Matrix PDF」能点了——三种文件（房源单 · History 报表 · 税务记录）各出一张待确认表，确认后属性卡 / 历史时间线 / 产权人（前几任）有内容，同一套房传第二份不会多出一套；税务记录只演示「业主姓名 + 转手日期 → 产权人」，别的字段等样例分析后定；② 房源详情加「历史时间线」（挂牌 → 调价 → 进合同 → 成交 → 转手 + 产权人起止 + 交易）、「＋ 产权人」手填（前任灰显）、「＋ 联系人」能点；③「标为目标房源」（原因 · 业主预计什么时候动 · 多久联系一次，到点今天页出「该联系」）和「标为某位客户的目标房」分开；④「＋ 创建交易 → 手动 → 卖房」可以当场新建房子和联系人，房源详情也能直接「建卖方交易」，建完落在「上市前」、第一步「上市委托协议」没完成 = 还在争取；没拿到就标「落选 · 撤回」，房源 / 业主 / 联系记录都留着；⑤ 经纪人 App 有房源页：全部 → 房源、搜索地址直达，手机上能加房源、看房源，现场四个动作（记业主 · 标目标房源 · 建卖方交易 · 拍照 / 上传）；示例数据加了一套争取中的 9090 Pursuit Ct（林先生）和一套落选的 2020 Bygone Dr（何女士）。
- v1.5：一个标准 + 三个新功能（Jason 10-03：「架构和流程按影子来，以影子为准」）。一个标准：影子里互相打架的地方统一成一种说法——「几天算快到了」和低置信线（0.9）只在一处；合同字段用真实的字段名；1234 Sample 的故事前后一致（Option 7 天 / $500 明天截止 · Offer v3 $520,000 → Amendment 改成 $515,000）；路线图节点显示同名里程碑的日期，没有才估算并标「估」；T1 提议自动执行不出卡，T3 只有 Broker 能批，拒绝要写原因，撤销连它建的记录一起撤；客户点「同意」只记时间，对方签字才成合同；合规清单分四段，一次提交「合规 + CDA」；续约提醒 90 / 60 / 30；d7 的申请人只有刘先生一位。三个新功能：① 摘要语句 v0——交易概览顶上一张「摘要」卡，56 句 + 10 组，可隐藏 / 改字 / 临时加一句 / 两句合并，客户不可见的句子进不了客户 App；② 邮件「待归档」+ 交易沟通时间线——没归上交易的邮件单独一块（归到… / 忽略 / 以后都忽略这个发件人），沟通 tab 把邮件 · 电话 · 微信 · 短信 · 记一下 · 会面 · 日历 · 看房 · 消息合成一条线，超过 24 小时没回的标「待回复」；自己约的看房确认后进日历，别人看我挂牌的进看房反馈；③ 扫描件 · 手写 · 拍照——文件分电子 / 扫描 / 拍照，字段带来源（打印 / 手写 / 勾选）和裁图，交叉校验 4 项，「确认全部」一次收下电子版里 ≥ 0.9、校验没问题的每一行（钱和日期也在内），扫描 / 手写 / 拍照、低于 0.9、卡在校验上的逐条确认，其中钱和日期先看裁图；系统自己从不确认任何一格。影子说明页加「演示简化」和「手册里有、影子没画的」两张单子；覆盖表改成开工手册 v60 的步骤号。
